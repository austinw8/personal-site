I joined the Legrande dev team a little less than a year ago, stepping into a project that’s very much alive and active. It’s a full-stack web app using Javascript React on the frontend, FastAPI/Python on the backend, a PostgreSQL database, with Firebase frontend hosting and Google Cloud Run backend hosting using Docker containers.

This has been my favorite project to work on to date, but also the most challenging. Here are a few of the biggest lessons I’ve taken away so far.

### 1. Ask Questions Early...And Ask Better Ones

I used to think “good developers just figure things out,” so I’d nod along, pretend I understood everything, then waste hours trying to reverse engineer what someone actually wanted. Asking direct questions, especially the _“why”_ behind a request, has been a game-changer. Most people describe symptoms, not the real problem, and digging deeper helps me avoid building the wrong thing. Watching senior devs casually ask “basic” questions made me realize staying quiet wasn’t confidence, it was self-sabotage.

### 2. Mistakes ≠ Failure.

I used to take every bug personally, like each one confirmed I was the weak link on the team. Over time, I realized even great developers break things constantly. It's just part of the software developing process.

Code is iterative. You build, you test, you adjust, you patch, you learn. That’s normal. Once I stopped viewing bugs as personal flaws, everything became easier. I still aim to get things right on the first try, but when something slips through the cracks, I fix it and move on. My manager even jokes that bugs are a good sign because it means people are actually using the things I build.

### 3. Ship Early and Ship Often

If this project had a motto, it'd be something like "**Perfect is expensive. Progress is priceless.**". We release new features constantly! Sometimes they're big features, but often they're small features, little incremental improvements, cleaned-up logic, or tiny UX improvements. We don't ship sloppy code, but we like shipping code that gives the users _something_ to work with, then we can go back and iterate on their feedback.

## Closing Thoughts

Working on this app has stretched me, humbled me, and made me a better developer in a surprisingly short time. I’ve learned to ask questions without fear, to treat mistakes as stepping stones, and to keep shipping instead of obsessing over perfection.

I'm excited about this project because there's a lot more to learn, and this project is the perfect place to learn it.
